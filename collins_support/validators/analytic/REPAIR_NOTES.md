# v0.5.1 repair notes

The reviewed v0.5.0 bundle identified two actual validator failures and a further dependency-test defect. This release repairs the validator only; production remains the implementation agent's responsibility.

1. `native_subtropica.wls` now sets `SetOptions[HyperIntica`HyperInt, "EvaluatePeriodsQ" -> True]`, matching the pinned SIDIS s10/s13 invocation. It saves raw results and masters, then requires exact scalar transport before its local PASS receipt. The runner still performs a separate native reexport. This avoids the old misleading local PASS on malformed Total/Derivative output.
2. `compare_ru_reports.py` handles reports blocked before retained replay. Valid early BLOCKED reports yield a saved BLOCKED pair; malformed or FAIL reports remain failures. Passing-report checks, report preservation and output-path protections remain in force.
3. The Kira probe now scales the entire audited reduction map. Explicit raw rules are scaled as before. Missing target rules are accepted only when the baseline certificate identifies an actual surviving master identity; those scaled identities are added to a disposable raw-rule file. The independent auditor reconstructs the new map; `native_probe_audit.wls` requires every rule to equal the exact seeded multiple, with unchanged targets/master inventory. The evaluated masters remain unchanged, and the original fixed-recipe/downstream-response checks still apply. No producing expression is changed to manufacture a probe response.

In the reported quark example, the direct-master contribution is -2 CF times the master. Scaling only the other rules cannot uniformly scale the total contraction. Explicitly perturbing the complete map makes the original uniform response requirement mathematically correct. This is a nonphysical software dependency test; copied probe inputs must never be described as a fresh physical reduction.

`upgrade.py` verifies the exact previous release, old acceptance and current new-engine/runtime identities, and records preservation snapshots in a new state. It does not patch either implementation or the old validator. New official workflows must run under the new release; old reports are never promoted. `install.py` remains only for an absent engine.

`native_regression.py` uses a real two-cut Kira job and derived Euler inputs for two real SubTropica evaluations. It checks the volume against an independent Gamma expansion, the eikonal master against actual Kira output, three reduction coefficients against beta identities, and the full mixed contraction under both seeded map probes. A period-disabled copy is an explicitly labelled negative control and must fail before a PASS receipt. All outputs are outside the package and the producing engines.

The exact arithmetic engine, schema-5 candidate packets, accepted-source snapshot, 167 comparison values, eleven required sectors, 20-file SIDIS approval list, old literature inventory and retained v0.4.0/v0.3.3 validators are unchanged. The contract differs only in its release version. No Collins sign, z/Fourier factor, subtraction convention, physical endpoint class or radius qualification is altered. The remaining measured TMD/HF/soft/jet derivations and full assembly are still required.
